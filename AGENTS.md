## Before starting

Read the README and any notes relevant to the task. Use `Project Home.md`
for system work and `Dataset Guide.md` for dataset work. Read both sides
when the task affects both. Consult `scripts/SAMPLE_TRAINING.md` in the
system folder for dataset preparation and training.

## Record substantial work

Before making changes, create one work note for a substantial task, such
as importing a dataset batch, retraining, changing the active model, or
implementing NLP. Use a dated title. Record the goal, the relevant files
or versions, and how you plan to verify the work.

Keep dataset and retraining notes in the dataset vault. Keep app and NLP
notes in the system vault. For work that spans both, use one note in the
vault that owns the main task and link to it from both landing notes.

Reuse the same note when continuing the task in a later turn or chat.
Update it at meaningful milestones and when the task is finished or
handed off. Record what changed, what was verified, links to the results,
and any blocker or next action.

For retraining, record the baseline, candidate version, evaluation link,
and the decision about using the candidate in the app. If the active
model changes, record the previous model and how to restore it.

Link the work note from `Project Home.md` or `Dataset Guide.md` as
appropriate. Keep reusable setup and workflow details in the READMEs
and detailed training results in the run report.

## Conversation logs

Use `Conversation Log.md` when a past discussion is relevant or when the
user asks to capture a discussion. Quick questions and minor edits do
not need a work note. Keep credentials and secret values out of all notes
and logs. If a vault is unavailable, continue with the context you have
and tell the user which vault you could not access.
